# 调度规则

定时任务**不属于 skill 本身**，只能由 Agent 在用户单独授权后创建。本文给通用模板与硬约束。

## 只在开盘时段跑

- 采用**多条单整点规则**，每条任务只在一个整点触发一次。
- **禁止** `FREQ=HOURLY` + 多 `BYHOUR` 的「一条任务搞定」写法：实测某些调度器会接受该规则，但把 `nextRunAt` 算到深夜，变成全天轮询且无报错。
- 规则形如 `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=<单值>;BYMINUTE=0`。
- 创建后**逐条换算时区**核对 `nextRunAt`，确认全部落在预期整点。
- 节假日调度层排除不了：任务内第一步用交易日历判断，非交易日立即静默退出（不取数、不自检、不写文件、不发消息）。
- A 股 / 港股**分别**判断交易日与交易时段（休市日与午休时段不同）。
- 收盘那一次负责日汇总、净值埋点、除权检测，不是盘中空跑。

## 引擎分离

财报、价格、买入区间是三件频率完全不同的事，别揉成「每小时跑一次的大任务」：

| 链路 | 频率 | 职责 |
|---|---|---|
| 财报监控 | 低频、事件驱动 | 检测新报告期/新公告 → 生成对比分析 → **重算该股买入区间** → 重建详情页与首页 → 速递 |
| 价格引擎 | 开盘时段 | 取快照 → 本地脚本做规则比对 → 仅触发时推送 |
| 区间基准库 | 离线研究产物 | 低频维护，价格引擎只读 |

**最有价值的联动**：静态区间在财报、除权除息、商品价格大动后会立刻失效，财报发布必须触发重算。

## 降噪

- 纯数值判定放本地 Python 脚本（可复现、可回测），定时任务只负责触发 + 读结果 + 决定是否推送。
- `state/dedupe.json` 记录已推送档位，**同一档位只推一次**，写入采用先读后写。
- 无买点不推送；收盘给一条「今日无触发 / 今日触发汇总」日汇总，避免误以为系统坏了。
- 告警分三档：信息型 / 需注意 / 需行动。什么都紧急等于什么都不紧急。
- `reference` 置信度的标的触发时，推送必须附「参考级 / 低置信度、需人工确认」。

## 数据源降级

- 取数前先跑 `python scripts/check_sources.py --root <实例目录>`，读 `state/source-health.json`。
- 不可用源：跳过全部该源调用、不重试、不等待、不请求重连、不报错中断。
- 端点恢复且工具注册成功后：自动补取缺失分位 → 把 `confidence` 从 `reference` 升回 `standard` → 重算区间 → 重建页面。
- MCP 调用串行、控制并发（部分源有 QPS 限制）；财报引擎与价格引擎时点错开。

## 通知

- 通道做成可替换适配器：企业微信 / 邮件 / 仅本地文件 / 关闭。
- 通知正文只带文本摘要 + 关键数字；**不要放本地 HTML 路径**（手机上点不开）、不要暴露持仓金额细节。
- 默认向当前授权人发送；群聊、指定收件人需用户明确指定。
- App 原生提醒写入是**真实改动账户设置**的写操作，且常为全量覆盖语义；需单独授权，改前先读回全部字段回填。
